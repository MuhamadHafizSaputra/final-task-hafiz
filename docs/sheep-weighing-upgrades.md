# Four upgrades to investigate for the sheep-weighing capstone

22 November 2026. The candidates below address a physical weighing session, data transfer, measurement quality, and a future marketplace. Each is a separate capstone option. The [original scope](project-context.md) and [Hafiz–Lutfi handoff](project-handoff-context.md) already cover automatic weighing, a mobile preview, tag correction, and backend processing. The existing interrupted-pass proposal concerns recovering lost samples from one pass. Here the question is what goes wrong even when the samples arrive.

## 1. Account for every sheep before the pen is released

**Farm decision.** An operator expects 20 sheep and sees 20 rows on the phone. One sheep could have appeared twice while another crossed without a usable tag. The totals would agree even though the records are incomplete. A valid result requires a distinct expected sheep, a usable weighing, and an identity that can be supported.

**What exists.** iLivestock already compares scans against a group and distinguishes an animal scanned earlier in the session. Gallagher already links locked weights to electronic identification (EID) and supports visual ID entry. An Australian sheep EID report describes adjacent animals and changes in the antenna read zone as causes of reading problems. An Australian processing trial also integrated electronic ID with independent count verification. Group comparison, duplicate warnings, and independent counting all have precedents. [iLivestock Drafter](https://help.ilivestock.com/en/articles/6420056-drafter-separating-animals-ios-only) · [Gallagher weighing guide](https://search.am.gallagher.com/media/4864/tsi_set_up_guide_weighting_with_eid.pdf) · [Western Australian sheep EID report, §13.1.6](https://www.agric.wa.gov.au/sites/gateway/files/Opportunities%20for%20Individual%20Animal%20Management%20of%20Sheep%20in%20Western%20Australia.pdf) · [AMPC sheep EID trial](https://ampc.com.au/media/naihp4ai/final-report-2025-1070-sheep-eid-identification-technology-assessment.pdf)

**Candidate upgrade.** Freeze the expected pen list at the start of the session. Keep a record of each attempted crossing, including passes without a final weight. Before releasing the pen, show which expected sheep have an accepted weight, which were positively identified but need another weighing, which passes lack an ID, and which expected IDs have no confirmed result. Open the relevant pass for a visual tag check or reweigh. A missing ID on the roster and an unidentified pass are separate facts until someone verifies the link. Two animals in one gate event can also defeat the counter. Preserve uncertainty and record any deliberate decision to close with exceptions.

**Contribution to test.** Can combining the expected roster, independent evidence of crossings, and weighing outcomes reveal more incorrectly completed sessions while the animals are still accessible? Use a roster-and-EID checklist with repeat-scan warnings as the baseline. Compare both methods against an independent observer's visual IDs and accepted reference weights. Include returns, adjacent tags, an unexpected sheep, and an animal that never entered. Measure sessions incorrectly declared complete, wrong identity assignments, unresolved cases, and minutes to release the pen. Report real and staged incidents separately. Lutfi supplies timestamped gate and tag events; Hafiz owns the session logic and operator screens. A reliable roster and an operator who can still retrieve animals are prerequisites.

## 2. Import one physical weighing once and keep genuine same-day reweighs

**Farm decision.** A worker imports a scale file. Later the device reconnects, an overlapping export arrives, or someone imports the file again. Two identical rows may represent a duplicate transmission or two genuine weighings. Overwriting by date can erase evidence the operator needs.

**What exists.** Datamars documents that importing the same session twice creates duplicate sessions requiring manual deletion. Shearwell's FarmWorks CSV guide says the last imported weight for an animal on the same date replaces its earlier weight. AgriWebb documents a workflow for moving Optiweigh weights through CSV. In New Zealand workshops, sheep and beef farming end users identified a need for data to move accurately between systems and users. These findings describe the named workflows and establish a problem worth checking locally. [Datamars PC upload](https://support.livestock.datamars.com/en/articles/14190116-uploading-files-from-a-pc-to-datamars-livestock) · [Shearwell CSV weight import](https://static.shearwell.com/Content/UK/Support/Downloads/CommonQuestions/CSV_Import_Weights.pdf) · [AgriWebb import workflow](https://help.agriwebb.com/en/articles/12825191-uploading-weight-records-from-optiweigh-iam) · [Journal of New Zealand Grasslands, farmer workshops](https://doi.org/10.33584/jnzg.2023.85.3660)

**Candidate upgrade.** Give each physical pass a persistent ID scoped to the farm and device, and carry it through the live upload, SD replay, and export. Repeated evidence for the same pass should yield one official record. A second pass may legitimately have the same animal, date, and weight. Keep it when its pass ID differs. If two sources disagree on the same pass, retain their values and surface the conflict. For outside files lacking a pass ID, record the source and show ambiguous matches to the operator. Date and rounded weight alone can be identical in two different events. Never auto-merge on those fields alone.

**Contribution to test.** Under common file-transfer mistakes, can the app preserve the correct weighing history with less manual cleanup? Compare accepting all rows, replacing by animal and day, recognizing identical files, and matching individual passes across overlapping sources. Use labeled full, partial, reordered, and repeated exports; two real same-day passes with equal weights; an edited row; concurrent imports; and an interrupted upload followed by retry. Count real passes lost, duplicate official records, unresolved rows, and operator time. Test native pass IDs separately from legacy CSV. This extends sample-level MQTT deduplication into a distinct user problem. Hafiz can prototype it on the app/backend with exported sessions. If the partner only has one automatic input and never transfers or corrects records, ordinary retry protection may be sufficient.

## 3. Catch a steady reading while the sheep is partly off the platform

**Farm decision.** A sheep pauses with its front feet on the scale. Its weight trace can be steady enough to pass a numerical stability rule. At that instant the operator needs a specific instruction, such as “check rear feet,” before recording the weight.

**What exists.** An Indonesian IPB prototype already integrates a load cell, HX711, RFID, ESP32, and web interface for sheep. A UNESA prototype also combines sheep identification and weighing. Bates et al. discuss a front-legs-only event as a source of error in sheep weighing. Published patents describe estimating position from inlet and exit loads and triggering a weighing from a photocell placed according to animal size. These are direct precedents for both the hardware combination and checking position. [IPB repository, abstract](https://repository.ipb.ac.id/handle/123456789/163209) · [UNESA article, abstract](https://ejournal.unesa.ac.id/index.php/jurnal-rekayasa-mesin/article/view/54442) · [Bates et al., sheep weighing study](https://doi.org/10.1016/j.compag.2023.107631) · [Inlet/exit load patent](https://patents.google.com/patent/US20050006153A1/en) · [Photocell patent](https://patents.google.com/patent/EP3173751A1)

**Candidate upgrade.** Determine which observable cue earns its cost on Lutfi's actual crate. First test stability plus the current beam. If false acceptances occur, compare with a second boundary beam or separately measured front and rear loads, depending on what the platform supports. Use the added evidence to prompt an immediate check, then reassess the pass. A single beam senses a body at one location. Even two torso-level beams cannot certify the location of every hoof, and contact with a side rail may offload weight. When the evidence is inconclusive, offer an operator check.

**Contribution to test.** Use observer or video labels for full support, partial entry, backing out, and two animals touching the platform. Pair accepted readings with independent reference weights. Compare stability alone, stability plus the existing beam, and the added cue on the same recorded passes. Report false acceptance of partial readings, error of accepted weights, unnecessary prompts on valid passes, seconds per sheep, and incremental hardware cost. Split the evaluation by animal and session. If the crate already physically prevents the error, or operator inspection performs equally well, an extra sensor has little value. This is a practical comparative evaluation; position sensing itself is established.

## 4. Show exactly which sheep support a sale lot's advertised weight

**Buyer decision.** A buyer asks for ten sheep within a weight band. Seven distinct sheep have recent qualifying records, one has a recent weight outside the band, and two have no current verified weight. The seller can substantiate seven. The possible count is seven to nine under the chosen date and measurement rules. No growth model or random-sampling assumption is needed for that statement.

**What exists.** AuctionsPlus already publishes sheep assessment guidance on representative sampling, including avoiding a sample drawn only from the front or back of a group. Its marketplace also describes publishing individual assessment weights for sale lots. Its assessor instructions cover amendments to a catalogued assessment. In Indonesia, Nirmala Farm already displays weights for individually listed sheep. Showing kilograms, a sampling percentage, or an editable listing has direct precedents. [AuctionsPlus assessment manual](https://5152284.fs1.hubspotusercontent-na1.net/hubfs/5152284/Sheep%20Assessment%20Manual%202024.pdf) · [AuctionsPlus explanation of weighed samples](https://pulse.auctionsplus.com.au/toolbox/does-weighing-more-of-the-mob-increase-value) · [AuctionsPlus assessor instructions](https://localmedia.auctionsplus.com.au/Doc/HINTS-AND-TIPS-FOR-ENTERING-ASSESSMENTS-ON-AUCTIONSPLUS.pdf) · [Nirmala Farm sheep catalogue](https://www.nirmalafarm.com/)

**Candidate upgrade.** Generate a buyer-facing weight statement from the exact IDs in a lot, each animal's accepted measurement, and the measurement date. State the weighing date or agreed freshness window. Count each ID once. If an animal is substituted or an ID or weight is corrected, recompute the statement and show what changed alongside the originally offered version. The information describes recorded weights at assessment. A buyer and seller would need to agree separately about any pickup-weight requirement.

**Contribution to test.** Does linking a lot claim to the underlying pass records reduce unsupported seller statements and help buyers identify exactly what is evidenced? Compare a conventional listing that already shows average, range, and sample count with the proposed screen on identical lots. Include edited lots, repeated passes, expired observations, and a correction after publication. Measure unsupported statements that survive an edit, buyer accuracy when interpreting the claim, and seller preparation time. Use a listing-preview prototype; a payment system adds nothing to the test. If the partner always sells one named sheep at a time, the group-level research question has little local relevance.

## Recommendation for fieldwork

Observe one weighing run from pen entry to release and follow the resulting file or record to its next user. Count how many animals were expected, how many physical crossings occurred, which records required correction, and whether records were transferred or reused. Ask to see one real sale listing and establish whether it represents a named sheep or a group. These observations distinguish the four project options more reliably than a feature preference survey.

The strongest joint capstone candidate is the first when the partner has a pen list and operators need to know when they can release the group. The second has the clearest published software limitations and offers the strongest app-only test when files and live records coexist. The third has a direct measurement outcome but substantial hardware prior art. The fourth is the closest to a buying system and depends on sales by lot.

**Evidence boundary.** This targeted English and Indonesian search used public journal and university records, sheep-industry field reports, patent descriptions, manufacturer manuals, and actual app and catalogue documentation. Previously implemented features are identified above. The proposed novelty is in the indicated operational improvement and comparison. A manual's silence does not establish that its product lacks a capability. Neither local demand nor worldwide novelty has been established. The supervisor's criterion remains open.
