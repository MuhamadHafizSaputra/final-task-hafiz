# Comparison: PWA Web App vs Native Mobile App (Project Context)

Date: 2026-11-12

Scope: Farmer data-capture mobile app for IoT goat weighing system (final-task scope).

## Comparison table

| Aspect | PWA web app | Native mobile app (Expo/React Native) |
|---|---|---|
| Nature | Web application using PWA technologies | Native mobile application |
| Installation | Browser install / Add to Home Screen | APK / Play Store / App Store |
| Offline operation | Yes, after first online load and caching | Yes, with local storage |
| Local database | IndexedDB | SQLite |
| ESP32/BLE access | Browser dependent; Web Bluetooth not supported on Safari iOS | Strong control via native BLE libraries |
| Background sync | Browser support limited; not supported Safari iOS | App-controlled retry and background mechanisms |
| Web Bluetooth | Supported on Chrome Android, Opera Android, Samsung Browser; unsupported Safari iOS | Supported via native libraries |
| Service worker / offline cache | Required for offline UI | Not required as PWA |
| Device storage control | Browser quota and user data clearing behavior | More predictable local persistence |
| App lifecycle / suspension | Browser may suspend | Native app can control lifecycle |
| Hardware streaming | Possible via BLE/Wi-Fi, subject to browser support | Better for continuous acquisition |
| Stable-weight computation | Possible in JS | Possible in JS/TS; more reliable field flow |
| Camera / photos | Browser supported with permission | Native camera integration with better control |
| Permissions | Browser/OS-dependent | Native permission flow |
| Development speed | Faster for web-based team | More setup, native config needed |
| Deployment/update | Server deploy; cache-busting handling | Store/APK release flow |
| Testing | Many browsers | Android/iOS devices |
| Security | HTTPS; token storage handled carefully | HTTPS; secure storage possible |
| Long-term field reliability | Medium-high risk with hardware access | High for current hardware scope |

## Offline-first behavior

### PWA

```text
Online first visit/install:
  -> download app files
  -> cache via service worker
  -> initialize IndexedDB

Offline later:
  -> open installed PWA
  -> cached UI
  -> local IndexedDB data
  -> sync queue waits for internet
```

Constraints:

- First use before first successful online load cannot open offline.
- Browser lifecycle may suspend background sync.
- Browser storage limits can vary.
- Web Bluetooth not supported on Safari iOS.

### Native mobile app

```text
Install app:
  -> core files present locally

Open app:
  -> local database works immediately

Offline:
  -> SQLite storage
  -> sync queue later
```

Constraints:

- Still needs internet for login, first server data, updates, sync.

## ESP32 connection feasibility

- If ESP32 exposes local HTTP API over Wi-Fi: PWA feasible.
- If ESP32 uses BLE for load cell/RFID: native app preferable; Web Bluetooth lacks iOS Safari support.

## Recommended final decision

For current final-task scope (field data capture, offline weighing, stable-weight detection):

- **Farmer data-capture app: Native mobile app (Expo/React Native).**
- Local storage: SQLite.
- Offline-first data capture + sync to Supabase.
- ESP32/BLE/RFID integration in native app.

Future marketplace and browser-facing interface: web app / PWA.

## Conclusion

Native mobile app is **better** than PWA for the current farmer data-capture context.

Rationale:

1. Hardware: ESP32 + BLE + RFID central.
2. Offline-first and raw sample storage are central.
3. SQLite supports local transaction better than IndexedDB.
4. Background sync and hardware connection reliability favor native.
5. Stable-weight detection is central research contribution; native is more controllable for testing.
6. Field reliability expected higher with native.

PWA remains viable for marketplace, dashboards, and admin; not for primary weighing field capture in this project.
